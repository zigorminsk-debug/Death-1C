# Очистка сеансов 1С (Session Cleaner for 1C)

Программа администратора сервера 1С:Предприятие: показывает все активные
сеансы кластера и **удаляет старые и задублированные сеансы по каждому
пользователю**, оставляя только самые актуальные. Интерфейс — обычная
HTML-страница, которая открывается отдельным окном; установщик —
классический `setup.exe` (NSIS). Вся сборка выполняется в **GitHub Actions**,
каждая сборка получает **порядковый номер** (`github.run_number`).

## Что умеет

| Возможность | Как |
|---|---|
| Список всех сеансов кластера 1С | кнопка **«Показать сеансы»** (прямое подключение к RAS, порт 1545, собственный бинарный протокол) |
| Удаление старых сеансов по пользователям | кнопка **«Удалить старые»**: в каждой группе «пользователь + база» остаётся только самый актуальный сеанс, остальные завершаются с пояснением для пользователя |
| Учётные данные вводятся один раз и больше не отображаются | настройки и пароли шифруются AES-256-GCM, ключ защищён DPAPI в `%ProgramData%\1C Session Cleaner\settings.dat`; интерфейс получает только маски вида `А***р` и признак «пароль сохранён» |
| Запуск всегда с правами администратора | манифест exe требует `administrator` — любой ярлык вызывает UAC; установщик создаёт ярлыки на рабочем столе и в меню «Пуск» |
| Настройки только через Shift | меню настроек открывается, если запустить программу с удерживаемым **Shift** (или ярлыком «Настройки»); обычный запуск идёт сразу на главный экран |
| Защита служебных сеансов | регламентные задания, консоль сервера, веб-сервер, COM-соединения и сеансы без имени не завершаются никогда |
| Службы 1С на сервере | из настроек видно состояние служб `ragent`/`ras`/`rmngr` и можно запустить остановленный сервер администрирования |
| Очистка по расписанию | консольный режим `-clean -yes` + задание планировщика (опция установщика) |
| Журнал действий | кто, когда и какие сеансы завершил; выгрузка в файл из интерфейса |

## Как этим пользоваться

1. Установите `SessionCleaner-Setup-<номер>.exe` (права администратора).
2. Запустите ярлык — программа откроется на экране настроек: укажите сервер
   1С (`имя:1545`), администратора кластера и, при необходимости,
   администратора Windows-сервера. Нажмите «Сохранить настройки».
3. Дальше обычный запуск открывает главный экран:
   **«Показать сеансы»** → таблица всех сеансов с решением программы →
   **«Удалить старые»** → план с подтверждением → сеансы завершены,
   актуальные остались.
4. Меню настроек — запуск с удерживаемым **Shift**.

Консольный режим (планировщик, скрипты):

```
SessionCleaner.exe -console            список сеансов текстом
SessionCleaner.exe -clean -dry-run     показать план, ничего не завершая
SessionCleaner.exe -clean -yes         завершить старые сеансы
SessionCleaner.exe -settings           открыть меню настроек
SessionCleaner.exe -version            сведения о сборке
```

## Сборка (только GitHub Actions)

Локальная сборка не нужна и не поддерживается: рабочий процесс
`.github/workflows/build.yml` сам собирает exe и установщик.

1. Пуш в любую ветку (или `workflow_dispatch`) → job `check`
   (`gofmt`, `go vet`, `go test` на Ubuntu) → job `build` на `windows-latest`.
2. Порядковый номер сборки = `github.run_number`; он попадает в
   `-ldflags -X .../buildinfo.Build`, в версию файла (`1.0.0.<номер>`),
   в имя установщика и в имя артефакта:
   `SessionCleaner-Setup-<номер>.exe`.
3. Шаги сборки: `go test` → `go-winres make` (иконка, манифест
   `requireAdministrator`, DPI, версия) → `go build -H windowsgui` →
   `makensis installer/setup.nsi` → артефакты (хранятся 90 дней).
4. Тег `v*` дополнительно создаёт GitHub Release с тем же номером сборки.

Артефакты скачиваются на странице Actions соответствующего запуска
(блок **Artifacts**).

## Устройство репозитория

```
cmd/sessioncleaner        точка входа: окно, Shift, UAC, консольный режим
internal/ui               локальный HTTP-сервер интерфейса (127.0.0.1, токен
                          сессии, CSP) + static/: index.html, app.css, app.js
internal/app              прикладной слой: состояние, план, выполнение,
                          проверка подключений, служба RAS
internal/cleaner          правило очистки: группировка, ранжирование, план
internal/ras              бинарный протокол RAS 8.3 (handshake, endpoints,
                          сообщения GetSessions/TerminateSession и др.)
internal/rascodec         примитивы кодирования 1С (varint, nullable, uuid, time)
internal/config           настройки и их валидация
internal/securestore      шифрование настроек: DPAPI + AES-256-GCM, ACL каталога
internal/winexec          выполнение команд на Windows-сервере от имени администратора
internal/winsvc           службы 1С на сервере: список, запуск, перезапуск
internal/platform         Shift, UAC, single-instance, открытие окна и ссылок
internal/logger           журнал с ротацией
internal/buildinfo        версия, номер сборки, контакты разработчика
installer/setup.nsi       установщик NSIS (русский, MUI2)
assets/winres             winres.json + иконка для ресурсов exe
assets/icon               иконки приложения и установщика (ico/png)
.github/workflows         сборка с порядковыми номерами
```

Тесты (`go test ./...`) покрывают кодек RAS, клиент протокола (включая
проверку точных байтов кадра) и правило очистки; сетевые вызовы в тестах
заменены встроенным mock-сервером RAS.

## Безопасность интерфейса

- HTTP-сервер слушает только `127.0.0.1` на случайном порту;
- каждый запрос API обязан нести одноразовый токен, который выдаётся только
  вместе со страницей (заголовок `X-Session-Token`) и проверяется заодно по
  заголовку `Host`;
- CSP `default-src 'self'; script-src 'self'` — без inline-скриптов;
- секреты никогда не отдаются в браузер: ни в HTML, ни в JSON ответов;
- ссылки `mailto:`/`tel:` разработчика открываются системным обработчиком
  через отдельный API-запрос с whitelist схем.
